Use related resources to surface a small, curated set of links to supporting content at the end of a page. This helps users find what they might need next without competing with the main content.

## When to use

Use related resources when:

- there are two to four closely related pages a user is likely to need after reading the current page
- the linked content genuinely extends or supports the current page — not a generic 'see also' list
- users have finished reading and are ready for a next action or related context

## When not to use

- If there is only one related item, link to it inline in the body text instead.
- If the items are a next-step sequence — for example, step 2 follows step 1 — use [Next step]({% link _components/next-step.md %}) instead.
- If the items are general reference material not specific to this page, omit or curate more carefully.

## Placement

Place related resources at the end of the page, after the main content and before the footer. Do not place it mid-page or above the main content.

## Content rules

- Include two to four items only. A longer list signals a lack of editorial curation.
- Write titles that match the H1 of the destination page exactly. Do not write alternative titles for the same content.
- Do not use generic headings such as 'Related links' or 'See also'. Use a heading that describes what the linked pages have in common, or use the component's default label.

## Format

**Card grid (preferred)** — use a grid of two to four cards. Each card shows the destination title and a short description. Use this format when the related items are distinct content pages that benefit from a brief summary.

**[Feature link list]({% link _components/feature-link-list.md %})** — use when the related items appear in a sidebar or narrow-column layout where a card grid is not appropriate.

## Related components

- [Feature link list]({% link _components/feature-link-list.md %}) — for related resources in sidebar or narrow-column layouts.
- [Manual list]({% link _components/manual-list.md %}) — for a manually curated list without card treatment.
- [Next step]({% link _components/next-step.md %}) — use instead of related resources when the linked content is the sequential next step.
